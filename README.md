# Личный кабинет с авторизацией

Учебное веб-приложение: регистрация, вход, личный кабинет, выход и персональные напоминания. Стек: Python, Flask, SQLAlchemy, SQLite, Jinja2, APScheduler. Внешние сервисы и учётные записи не нужны.

## Быстрый запуск

Нужен Python 3.11 или новее. Откройте терминал в папке `project`.

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Linux / macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Откройте http://127.0.0.1:5000. Таблицы SQLite создаются автоматически в `instance/accounts.sqlite3`.

Во втором терминале из той же папки запустите планировщик:

```powershell
.\.venv\Scripts\python.exe worker.py
```

На Linux/macOS: `.venv/bin/python worker.py`. Оба процесса должны работать одновременно. Остановка каждого: Ctrl+C. Планировщик проверяет сроки в начале каждой минуты (`:00`), также выполняет проверку сразу при запуске. Он работает отдельным процессом и не запускается повторно из-за перезагрузки Flask.

## Пример использования

1. Откройте `/register`. Логин: `alice`, email: `alice@example.com`, пароль: `My-secret-password-2026`. Отправьте форму — это `POST /register`.
2. На `/login` введите `alice` и тот же пароль. Форма отправит `POST /login`, после чего откроется `/profile`.
3. В кабинете видны логин, email, дата регистрации, настройки доступа и собственные объекты — напоминания.
4. Добавьте сообщение «Подготовить отчёт» и выберите дату и время в календаре, например 20 декабря 2026 года, 15:30. Используется местное время компьютера. Под полем показана выбранная дата в формате `ДД.ММ.ГГГГ ЧЧ:ММ`. Это `POST /reminders`.
5. В начале назначенной минуты планировщик публикует сообщение в уведомлениях владельца. Открытый кабинет проверяет доставку раз в минуту, через 2 секунды после её начала (`:02`), включая первый запрос после открытия страницы. Например, срок 15:30:00 обрабатывается планировщиком в 15:30:00, а браузер проверяет доставку в 15:30:02. Новое доставленное сообщение открывается модальным всплывающим окном с кнопкой «Понятно». Перезагрузка не требуется, заполнение новой формы не прерывается. При создании уже просроченного напоминания доставка происходит на ближайшей проверке в начале минуты. Фоновая вкладка, спящий компьютер или задержка сервера могут отложить появление окна; две секунды — расписание опроса, а не гарантия времени доставки. Внешняя отправка в Telegram, email или системные push в проекте не предусмотрена: канал доставки — личный кабинет.
6. Прошедшая дата разрешена: сообщение доставляется при ближайшей проверке. После простоя планировщик обрабатывает все пропущенные сроки; состояние сохраняется в SQLite. Повторная проверка не доставляет сообщение повторно.
7. Кнопка «Удалить» отправляет `POST /reminders/<id>/delete`. Кнопка «Выйти» — `POST /logout`.
8. Зарегистрируйте второго пользователя в другом браузере: он не увидит объекты первого и не сможет их удалить.

Формы принимают `application/x-www-form-urlencoded`, а не JSON. Каждый POST требует CSRF-токен из формы и соответствующий cookie. Поля регистрации: `username`, `email`, `password`, `csrf_token`. Поля входа: `username`, `password`, `csrf_token`. Примеры выше полностью воспроизводятся в браузере.

## Маршруты

| Метод | Путь | Действие |
|---|---|---|
| GET, POST | `/register` | Форма и регистрация |
| GET, POST | `/login` | Форма и вход |
| GET | `/profile` | Закрытый кабинет |
| GET | `/notifications` | JSON с идентификаторами доставленных уведомлений владельца |
| POST | `/logout` | Отзыв текущей сессии |
| POST | `/reminders` | Создание напоминания |
| POST | `/reminders/<id>/delete` | Удаление своего объекта |

Неавторизованный пользователь перенаправляется на вход. Неверные данные регистрации дают 400, занятый логин/email — 409, неверный пароль — 401. Попытка удалить чужой или отсутствующий объект даёт 404. GET `/logout` не завершает сессию: изменение состояния требует POST с CSRF-токеном.

## Безопасность

- Пароли хешируются Werkzeug scrypt с индивидуальной солью; открытые пароли в БД не записываются. Длина пароля: 12–128 символов.
- Логины и email нормализуются и имеют уникальные ограничения в БД. SQLAlchemy использует параметризованные запросы.
- Случайный токен сессии находится в подписанном cookie; на сервере хранится только его SHA-256-хеш. Сессия действует 8 часов, выход отзывает её в БД. Повторное использование старого cookie после выхода не работает.
- Все изменяющие запросы защищены CSRF. Cookie: HttpOnly, SameSite=Lax; `COOKIE_SECURE=1` включает Secure для HTTPS.
- Jinja2 экранирует пользовательский текст. Заголовки CSP, запрет iframe и запрет кеширования защищают страницы кабинета.
- Все запросы к объектам фильтруются по текущему пользователю. Клиент не задаёт владельца объекта.
- Время хранится в UTC. Календарь вводит местное время компьютера, JavaScript преобразует его в UTC перед отправкой. Даты регистрации и напоминаний отображаются в русском формате `ДД.ММ.ГГГГ ЧЧ:ММ` в часовом поясе компьютера посетителя. При переходе на летнее время несуществующий час отклоняется, при повторении часа выбирается первое вхождение. Напоминания и отметка доставки сохраняются в SQLite атомарно.
- Секрет подписи автоматически создаётся в `instance/secret.key`; его можно заменить переменной `SECRET_KEY`. Не публикуйте `instance/`, храните секрет и резервные копии БД с ограниченным доступом.

Это учебный MVP с локальным сервером. Для внешнего размещения нужны HTTPS, production WSGI-сервер, ограничение частоты попыток входа на уровне приложения или прокси, резервное копирование и управление секретами. Восстановление пароля, подтверждение email, изменение профиля, роли и аудит изменений в MVP не включены. Создание аккаунта открыто; ограничение регистрации сотрудниками компании требует отдельной политики приглашений.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты работают с временной SQLite и проверяют регистрацию, уникальность, хеширование, ошибочный вход, защиту кабинета, отзыв cookie после выхода, истечение сессии, CSRF, изоляцию данных, удаление, экранирование HTML, проверку часового пояса и однократную доставку просроченных напоминаний.

Для календаря и местного времени требуется JavaScript в браузере. Встроенный вид календаря зависит от браузера и настроек языка ОС; отображение сохранённых дат и подпись выбранной даты всегда русские. Серверный POST по-прежнему принимает `due_at` в ISO 8601 с часовым поясом; форма формирует его автоматически.

Дополнительные проверки преобразования времени (необязательный Node.js 22+):

```powershell
$env:TZ = 'Europe/Moscow'
node --test --test-isolation=none tests/time.test.mjs
$env:TZ = 'America/New_York'
node --test --test-isolation=none tests/time.test.mjs
```

## Структура

```text
project/
├── auth/              # Регистрация, вход, сессии, выход
├── database/          # SQLAlchemy
├── models/            # Users, login_sessions, reminders
├── templates/         # Jinja2
├── static/            # Адаптивные стили
├── tests/             # Интеграционные проверки
├── app.py             # Фабрика приложения и маршруты кабинета
├── worker.py          # Планировщик
├── requirements.txt
└── README.md
```

Таблица `users`: `id`, `username`, `email`, `password_hash`, `created_at`. Дополнительные таблицы: `login_sessions` (серверные сессии) и `reminders` (личные объекты и уведомления).
